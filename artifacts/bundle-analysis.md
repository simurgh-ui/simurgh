# Bundle analysis

Simurgh's positioned overlays now use the framework-neutral positioning and interaction layer in
`@simurgh-ui/core`. The adapters contain only the framework glue needed to connect references,
portals, event handlers, state, and teardown.

The enforced `pnpm bundle:size` report bundles each complete internal adapter entry with only its
framework peer dependencies externalized:

| Layer entry | Minified | Gzip | Brotli | Gzip budget |
| ----------- | -------: | ---: | -----: | ----------: |
| Core engine |  2,111 B | 906 B |  804 B |     5,120 B |
| React       |  7,218 B | 2,813 B | 2,524 B |   5,120 B |
| Vue         |  5,982 B | 2,277 B | 2,044 B |   5,120 B |
| Angular     |  6,177 B | 2,253 B | 2,012 B |   5,120 B |

The machine-readable measurements live in `artifacts/floating-layer-sizes.json` and are regenerated
by `scripts/check-floating-size.mjs`.

## Dependency audit

- React, Vue, Angular, the registry, and the CLI declare no Floating UI runtime dependency.
- The workspace lockfile contains no Floating UI package.
- Copied-source overlays install the shared internal adapter files instead of importing an external
  positioning package.
- Bundle tooling measures the complete internal layer directly and enforces the same 5 KiB gzip
  ceiling for every adapter.
- The reproducible pre-migration measurements remain in
  `artifacts/floating-ui-pre-migration-baseline.json` for historical comparison.

## Import-boundary guidance

Per-component subpaths remain the default recommendation. The `basic` entry excludes positioned
overlays, while `overlays` groups consumers that intentionally opt into positioning behavior. Lazy
overlay fixtures continue to prove that the layer stays out of initial application chunks when the
overlay entry is loaded on demand.

## React shared-chunk evaluation

The React adapter now uses genuine per-component source modules, so consumers no longer depend on
the earlier monolithic barrel implementation. The reproducible code-splitting measurements are
stored in `artifacts/react-code-splitting.json` and generated by
`pnpm bundle:react-splitting`.
