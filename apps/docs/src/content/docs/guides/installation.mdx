---
title: Installation
---

Run the initializer inside an Angular, React, or Vue application:

```sh
pnpm dlx @simurgh-ui/cli init
pnpm dlx @simurgh-ui/cli add dialog tabs checkbox
```

`init` detects the framework, writes `simurgh.json`, copies tokens and recipes, and installs the core and positioning dependencies. `add` writes one framework-native source file per component and preserves existing files unless `--overwrite` is supplied. Use `simurgh diff dialog` before adopting registry updates.

Import `tokens.css` for semantic variables and component recipes for the optional visual layer. Headless behavior does not depend on either stylesheet. Avoid importing the complete `recipes.css` catalog in production unless the application genuinely uses most components.

## Production imports

Prefer component subpaths so application bundlers receive the narrowest possible graph:

```tsx
import { Button } from '@simurgh-ui/react/button';
import '@simurgh-ui/styles/button.css';
```

Each component stylesheet includes the shared tokens, so applications can import only `button.css` in this example. Import `tokens.css` separately when an application consumes tokens without a component recipe.

The same pattern applies to Vue (`@simurgh-ui/vue/button`) and Angular (`@simurgh-ui/angular/button`). When several primitives are needed together, `@simurgh-ui/{framework}/basic` provides common non-floating controls, while `@simurgh-ui/{framework}/overlays` provides dialogs, menus, tooltips, and related positioned UI. The `basic` boundary intentionally excludes Floating UI.

Root adapter imports and `@simurgh-ui/styles/all.css` remain convenient opt-in aggregates. Use them when the complete catalog is genuinely required; component JavaScript and CSS subpaths are the recommended production default.

## Lazy-load overlays

Dialogs, menus, tooltips, and other positioned components include Floating UI. Keep that positioning code out of the initial application bundle by loading an overlay at its route or interaction boundary.

```tsx
// React
import { lazy } from 'react';

const Dialog = lazy(() =>
  import('@simurgh-ui/react/dialog').then((module) => ({
    default: module.Dialog,
  })),
);
```

```ts
// Vue
import { defineAsyncComponent } from 'vue';

const Dialog = defineAsyncComponent(() =>
  import('@simurgh-ui/vue/dialog').then((module) => module.Dialog),
);
```

```ts
// Angular route
{
  path: 'dialog-example',
  loadComponent: () =>
    import('@simurgh-ui/angular/dialog').then(
      (module) => module.DialogComponent,
    ),
}
```

Lazy loading moves the overlay and Floating UI into an asynchronous chunk. It does not reduce the total downloaded code when the overlay is opened, but it keeps that cost off the initial path.
